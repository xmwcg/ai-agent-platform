# NexMind by AIbak 全平台上线商业闭环审计

> 审计日期：2026-07-26
> 范围：`ai-agent-platform`、根目录 `dashboard`、生产域名 `aibak.site` / `www.aibak.site`
> 原则：正常功能不改；微信支付链路为保护区；以生产证据 > CI/集成测试 > 源码 > 历史文档为准。

## 一、结论摘要

当前平台不是“完全不能上线”，而是已经具备稳定基线，但存在 4 类会阻断商业上线或造成用户误判的问题：

1. **页面/静态资源**：用户给出的 `/team`、`/pricing`、`/points-center`、`/knowledge`、`/marketplace` 旧截图中的动态 chunk 错误，在当前生产入口已不复现；首页与当前 `client/dist/index.html` 使用同一 `index-DW85px1s.js`，这些旧 chunk 直接返回 200，生产路由冒烟无控制台错误。
2. **状态页/大屏连接**：`PlatformStatusPage` 请求不存在的 `/api/public-status`，并且默认请求浏览器本机 `127.0.0.1:9090`；生产用户会看到“状态服务暂时不可用”。`PlatformOpsMonitorPage` 同样默认 iframe 到本机地址，无法作为生产管理员大屏入口。
3. **工具箱交互/权益**：七类工具已列出，但分类子项点击会把 `activeCat` 改为 `creative-copywriting` 等非法分类；Tabs 的受控 `activeKey` 使用数组索引 `0` 而不是工具 key。`tier: pro/free` 只是元数据，通用 `AITool` 未消费，页面没有明确的升级/积分解锁闭环。
4. **监控数据真实性**：根目录 `dashboard/index.html` 的 KPI、柱图、趋势和告警仍由 `Math.random()` 驱动；文档里列出的 `/api/dashboard/full-health`、`/api/dashboard/membership-stats`、`/api/dashboard/fix/*` 等接口并未在主平台 Server 中注册。主平台已有 `/api/ops/snapshot`、`/api/ops/public`、`/api/ops/dashboard`，但 `/api/ops/dashboard` 当前部分服务状态与模型数量是硬编码，不能直接作为“全平台实时真相源”。

## 二、已验证正常项（保护区，不应随意改动）

- 生产首页、`/team`、`/pricing`、`/points-center`、`/knowledge`、`/marketplace`、`www` 根域名均返回 HTTP 200；当前生产入口与本地 dist 的 index chunk 一致。
- `https://aibak.site/api/health` 返回 HTTP 200，MongoDB 与 Redis 均为 connected。
- `https://aibak.site/api/ops/public` 返回 HTTP 200，匿名公开运营指标可用。
- `https://aibak.site/api/ai/models` 返回 HTTP 200，当前生产配置暴露 OpenAI、Agnes、CloudBase 等模型池；`/api/ai/test/agnes` 返回 connected=true。
- 免费 AI 对话 POST `/api/ai/chat` 当前返回 HTTP 200，旧截图中的 502 在本次复检未复现；但指定 `provider=cloudbase, model=hy3` 的返回没有可靠地体现 provider，需补充模型路由契约测试，不应直接改动现有可用 fallback。
- 前端测试：13 个测试文件、133/133 通过。
- 后端测试：107 个测试套件、953/953 通过。
- 微信支付相关生产门禁、套餐 id 契约、回调验签与履约测试均已有覆盖，保持原实现，后续只做只读回归。

## 三、确认的问题与最小修复方案

### P0：生产状态页请求不存在的接口

- 证据：`client/src/pages/PlatformStatusPage.tsx:7` 默认值为 `http://127.0.0.1:9090/api/public-status`。
- 生产证据：`GET https://aibak.site/api/public-status` -> 404 `{"error":"Route not found"}`；`GET https://aibak.site/api/ops/public` -> 200。
- 修复：改为同源 `/api/ops/public-status`，在 Server 增加匿名安全状态摘要；不暴露 hostname、内部端口、密钥或仓库信息。保留 15 秒刷新。
- 验证：生产未登录浏览器打开 `/platform-status`，必须显示状态、最近检查时间和模块摘要，不能再访问回环地址。

### P0：管理员运维台不能依赖用户本机回环地址

- 证据：`client/src/pages/PlatformOpsMonitorPage.tsx:6` 默认 `http://127.0.0.1:9090`；生产环境变量未在源码/构建配置中发现。
- 修复：把监控大屏核心能力内嵌到主平台管理员页，数据读取同源 `/api/ops/dashboard`；外部 dashboard 只作为可选展示入口，未配置时不显示“可用的本机 iframe”，而显示清晰的配置/权限状态。
- 安全：一键修复只允许后端白名单动作；不实现任意 shell、任意 URL、任意 DNS 切换。

### P1：工具箱分类点击与 Tabs 受控状态错误

- 证据：`client/src/pages/ToolsCenterPage.tsx:102` 子项 key 为 `${cat.key}-${t.key}`，但 `onClick` 直接 `setActiveCat(key)`；点击“文案生成”后 `tools["creative-copywriting"]` 不存在。
- 证据：同文件 `Tabs activeKey={Object.keys(array)[0]}` 得到 `"0"`，而 Tab key 是 `copywriting` / `ppt` 等。
- 修复：分类项只负责选择分类，子项点击解析出父分类并设置 `activeToolKey`；Tabs 的 activeKey 使用真实工具 key；保留当前已能打开的独立 `/xhs`、`/text2img` 路由。
- 验证：七类分类、每个工具、独立工具跳转、返回工具箱、移动端折叠菜单均回归。

### P1：工具权益没有形成可解释的商业闭环

- 证据：`ToolsCenterPage.tsx` 中存在 `tier: 'free' | 'pro'`，但 `AITool.tsx` 未接收 tier，也没有升级/积分按钮；所有工具统一调用 `aiAPI.chat`。
- 风险：页面看起来标注了 pro，但用户无法知道为何受限、何时消耗积分、如何升级；仅依赖通用 AI 对话额度无法区分工具权益。
- 最小方案：先不改支付/订单；新增统一工具权益读取（登录用户计划、免费次数、积分余额），在工具页显示“免费额度 / 会员专享 / 积分消耗”，由后端工具标识参与配额校验。无权限时只显示升级或积分购买入口，不伪造结果。
- 权益建议：免费版可使用创作/开发/办公基础工具的有限次数；专业版解锁分析/营销/商务高级工具；旗舰版提高调用量并解锁图像/视频/批量导出；积分包只购买按量调用，不替代会员权限。

### P1：监控大屏仍是模拟数据，接口契约与主平台不一致

- 证据：`dashboard/index.html:345`、`397`、`609` 等仍使用 `Math.random()` 生成 KPI、趋势和事件；`dashboard/docs/real-data.md` 明确写明当前为随机模拟。
- 证据：`dashboard/README.md` 约定的 `/api/dashboard/full-health`、`/api/dashboard/membership-stats`、`/api/dashboard/fix/*` 在主平台 `server/src/index.ts` 中未注册；现有接口是 `/api/ops/snapshot`、`/api/ops/public`、`/api/ops/dashboard`。
- 修复：以主平台 `/api/ops/dashboard` 为唯一聚合入口，补齐真实指标字段：基础设施、模块可用性、AI 调用/Token/成本、会员计划/余额/用量、订单转化、实时数据流、告警列表。随机数只允许在离线演示模式，不得在生产显示。
- 一键修复：先支持只读诊断与安全白名单动作（刷新缓存、重新拉取指标、重启受控服务的申请/任务队列）；任何服务器重启、DNS 切换、同步、支付相关操作必须单独鉴权、审计、确认。

### P1：模型选择与实际返回 provider 缺少可观测契约

- 生产证据：`GET /api/ai/models` 可用，`/api/ai/test/agnes` 为 connected；`/api/ai/test/cloudbase` 返回 connected=false；免费聊天 HTTP 200，但指定 `hy3/cloudbase` 时响应未返回明确 provider，实际内容也不能证明走了 hy3。
- 代码证据：`server/src/routes/ai.ts` 在网关失败后回退 `callCloudbaseChat`；`server/src/services/ai-agent.ts` 统一通过 gateway route，provider/model 的最终选择应记录。
- 修复：增加内部 trace 字段（provider、model、fallback、usage、latency），前端只展示安全的模型名称；为 `hy3`、`hy3-preview`、HY-Image 两个图像模型增加可用性/废弃模型契约测试。当前可用 provider 不重写，只补观测和失败提示。

### P2：品牌展示尚未统一到 NexMind by AIbak

- 证据：`client/index.html` 与 `brand/BRAND-BOOK.md` 已使用 `NexMind by AIbak`；但 `client/src/App.tsx:70` 的侧栏品牌常量仍为 `AIbak`，`AppFooter.tsx`、部分 ProjectGrade 文案仍只显示 AIbak。
- 修复：按照品牌手册统一为：英文主品牌 `NexMind`、中文平台品牌 `AIbak`、组合展示 `NexMind by AIbak`；不修改业务产品名（智评通、金网通、TranSync），不替换支付/订单标识。

## 四、商业闭环设计基线

```text
发现/SEO/公开体检
  -> 注册/登录
  -> 免费额度（AI 对话、生图、工具、知识库试看）
  -> 额度消耗可视化（次数、积分、Token、余额）
  -> 升级会员 / 购买积分包 / 购买知识产品
  -> 微信支付回调履约
  -> 权益立即生效
  -> 使用记录、账单、退款、客服、续费/推荐
```

必须在每个收费入口显示：价格、周期、权益、剩余免费次数/积分、扣费规则、解锁范围、订单状态和退款/客服入口。知识库与课程需明确“免费全文 / 免费试看页数 / 会员解锁 / 积分解锁”，不能只在详情页底部提示。

## 六、一周上线分批计划

### 第 1 批：当天可完成的阻断修复

- 状态页同源接口与生产回归。
- 工具箱分类/Tab 交互修复。
- 侧栏/页脚品牌统一。
- 新增关键回归测试，不触碰微信支付实现。

### 第 2 批：监控大屏真实数据接入

- `/api/ops/dashboard` 聚合真实数据并去除硬编码状态。
- 主平台管理员页内嵌 KPI、模块状态、会员与模型用量、告警详情。
- 一键修复只接安全白名单；无真实修复能力时显示“创建运维任务”，不得假装已修复。

### 第 3 批：商业权益可解释化

- 工具 tier 与会员/积分契约统一。
- 知识库/课程的试看规则、解锁按钮、余额/积分提示统一。
- 只做前端入口与后端权限契约补齐，不改微信支付金额、回调验签和履约主流程。

### 第 4 批：发布验收

- 前端构建、后端构建、前端/后端测试、发布契约。
- `aibak.site` 与 `www.aibak.site` 关键路由、静态 chunk、API health、匿名免费 AI、登录后用量、价格页、积分页、知识库、Marketplace、Team。
- 管理员大屏与普通用户状态页分别验证权限。
- 生成回滚包与问题清单；任何未能通过生产证据的功能标记为“待云端统一源站”而不宣称已上线。

## 七、当前不应动的内容

- 微信支付金额、支付渠道、回调验签、订单履约与退款核心逻辑。
- 已通过的登录/OAuth、ProjectGrade 公开体检安全门禁、课程/积分/账本现有测试。
- 当前生产正常的静态资源缓存与 SPA 回退策略。
- 已能正常调用的模型 provider 配置；仅补 provider/model/fallback 观测和契约测试。
